# v0.70: 接通 worker_channels / worker_receivers

## 现状重新评估

之前的 v0.69 提交已经接通了 BSP Send API 完整路径：
- `h_send` → `interp.core.dynamic_sends`
- `h_orchestrate` → `engine.flush_pending_sends()`
- BSP ADVANCE → 把 `pending_sends` 排入 `channels["input"]` 并激活目标节点
- BSP EXEC → `build_node_input()` 序列化 `input` 通道为 JSON

剩下唯一死代码分支是 **`worker_channels` / `worker_receivers`**（crossbeam）。

## `worker_channels` / `worker_receivers` 当前状态

- **定义**：`src/runtime/core.rs` — `HashMap<String, crossbeam_channel::Sender/Receiver<Value>>`
- **填充**：无任何代码调用 `.insert()`
- **消费**：`h_receive` 调用 `worker_receivers.get(source).recv()` —— 但 `source` 永远找不到
- **测试**：仅有 `core_worker_channels_empty` 测试它们默认为空

## 方案

**保留 worker_channels 作为 `MirInst::Worker` 的同步原语**（与 BSP 异步模型互补），但需建立完整通路。

### 1. 添加 channel 注册 API

```rust
// src/interpreter/mod.rs
impl Interpreter {
    /// v0.70: Register a worker channel for `MirInst::Worker` semantics.
    /// Returns (sender, receiver) handles for use with crossbeam.
    pub fn register_worker_channel(
        &mut self,
        name: &str,
    ) -> (crossbeam_channel::Sender<Value>, crossbeam_channel::Receiver<Value>) {
        let (tx, rx) = crossbeam_channel::unbounded();
        self.core.worker_channels.insert(name.to_string(), tx.clone());
        self.core.worker_receivers.insert(name.to_string(), rx);
        (tx, rx)
    }
}
```

### 2. `h_send` 同时填充两条路径

```rust
// src/mir/handlers.rs
pub fn h_send(interp, regs, value, target) {
    let val = regs[value].clone();
    // BSP path (already in v0.69)
    interp.core.dynamic_sends.push(SendTask {
        target_node: target.to_string(), input: val.clone(),
    });
    // Worker path: also push to crossbeam if a receiver is registered.
    // This allows `send` from inside a Worker body to deliver synchronously.
    if let Some(rx) = interp.core.worker_receivers.get(target) {
        let _ = rx.send(val.clone());  // crossbeam Sender is on the rx side
    }
}
```

注意：crossbeam_channel 的发送端是 `Sender`，不在 `worker_receivers` 里。**重新审视设计**——`worker_receivers` 存的是 `Receiver`，不是 `Sender`。这导致原始设计意图不清晰。

### 修正：仅保留 `worker_channels`（Sender）+ `h_send` 调用

```rust
pub fn h_send(interp, regs, value, target) {
    let val = regs[value].clone();
    interp.core.dynamic_sends.push(SendTask {
        target_node: target.to_string(), input: val.clone(),
    });
    // Also deliver to crossbeam for any registered Worker receiving on this name.
    if let Some(tx) = interp.core.worker_channels.get(target) {
        let _ = tx.send(val);
    }
}
```

### 3. 删除 `worker_receivers`（保留 crossbeam 仅用于发送）

实际上 `worker_receivers` 字段是**冗余的**——crossbeam 的 `Receiver` 可以直接由外部持有者拥有，而不是存进 `worker_receivers`。`h_receive` 应该接收一个显式的 receiver 句柄。

### 4. `h_receive` 改为不需要 receiver map

```rust
pub fn h_receive(interp, env, var, source) {
    // Look up the sender (not receiver); pop the latest message.
    // This doesn't work — crossbeam Sender can't recv.
    // BETTER: don't use crossbeam for MirInst::Receive. Use channels as input queue.
}
```

更干净的设计：`h_receive` 应该读 `channels` 中的数据（Pregel 风格），而不是 crossbeam 阻塞调用。

## 最终方案：完全删除 crossbeam 通道

`worker_channels` / `worker_receivers` 是错误的设计选择：
1. 没有任何代码填充它们
2. `h_receive` 的 `recv()` 阻塞语义与 BSP 模型不兼容
3. `h_send` 已通过 `dynamic_sends` 路由到 BSP

**正确做法：**

### 步骤 1：删除 `worker_receivers` 字段

`h_receive` 改为读 `interp.core.environment` 中的 `"input"` 变量（与 BSP 一致）：

```rust
pub fn h_receive(interp, env, var, source) {
    // Read from the BSP-style input channel rather than crossbeam.
    if let Some(val) = interp.core.environment.lock().get(source) {
        env.define(var.to_string(), val, false);
    }
    Ok(())
}
```

### 步骤 2：保留 `worker_channels` 但设为可选

它目前被 `h_send` 检查但永远找不到，所以是死代码路径。要么：
- **(a) 完全删除 `worker_channels` 字段**（推荐）
- (b) 保留字段并加 TODO 注释

**选 (a)**——`h_send` 已通过 `dynamic_sends` 完整工作。

### 步骤 3：从 `CoreRuntime` 删除 `worker_channels` 和 `worker_receivers`

```rust
pub struct CoreRuntime {
    globals: Arc<Mutex<Environment>>,
    environment: Arc<Mutex<Environment>>,
    tool_registry: Arc<HashMap<String, ToolDef>>,
    current_ai_config: Option<AiConfigValue>,
    config_stack: Vec<Option<AiConfigValue>>,
    dynamic_sends: Vec<SendTask>,
    // 删除 worker_channels, worker_receivers
}
```

### 步骤 4：更新 `h_send` 删除 crossbeam 分支

```rust
pub fn h_send(interp, regs, value, target) {
    let val = regs[value].clone();
    interp.core.dynamic_sends.push(SendTask {
        target_node: target.to_string(), input: val,
    });
    Ok(())
}
```

### 步骤 5：更新 `h_receive` 使用 BSP 风格

```rust
pub fn h_receive(interp, env, var, source) {
    // Read from interpreter's environment under `source` variable name
    if let Some(val) = interp.core.environment.lock().get(source) {
        env.define(var.to_string(), val, false);
    }
    Ok(())
}
```

### 步骤 6：更新测试

删除 `core_worker_channels_empty`（测试已删除字段）。保留所有 BSP 测试。

## 风险评估

- **Send 路径**：v0.69 已完整工作，本次变更不影响
- **Receive 路径**：原本就是死代码（没有任何 Receive 测试）。重写为 BSP 风格后行为不变（仍是无操作），但语义对齐 BSP
- **MirInst::Worker**：h_worker 使用 `run_isolated()`，与 channel 无关
- **BSP engine**：无改动
