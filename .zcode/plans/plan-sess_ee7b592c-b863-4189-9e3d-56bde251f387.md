# v0.87: gensym() / read() / macroexpand() 实现计划

## 设计原则（§0 完整实现）

三个 builtin 都遵循 `eval`/`apply`/`quote` 已有的 string-match 分派模式（`dispatch.rs:85-111`），不引入 `BuiltinKind` 新变体，不修改 `Value` enum，不增加全局注册。gensym 的计数状态放在 `CoreRuntime` 上，`Arc<Mutex<>>` 保护，支持跨线程（Pregel worker 场景）安全。

## 具体改动

### 1. `src/runtime/core.rs` — 添加 gensym 计数器

在 `CoreRuntime` 结构体添加：
```rust
pub(crate) gensym_counter: Arc<Mutex<usize>>,
```

在 `Default::default()` 和 `Clone::clone()` 中初始化：
```rust
gensym_counter: Arc::new(Mutex::new(0)),
```

### 2. `src/interpreter/dispatch.rs` — 添加三个 match arm + 三个方法

在 `call_function` 的 match 中（`dispatch.rs:111` 之后）添加：
```rust
"gensym" => self.call_builtin_gensym(args),
"read" => self.call_builtin_read(args),
"macroexpand" => self.call_builtin_macroexpand(args, env),
```

新增三个方法：

**`call_builtin_gensym(args)`** — 生成唯一符号名
- 从 `self.core.gensym_counter` 取并递增
- 返回 `Value::String(format!("g{}", n))`

**`call_builtin_read(args)`** — 解析源码字符串为 `Value::Code`
- 输入 `Value::String` → `Ok(Value::Code(source))`
- 与 `quote()` 对称：`quote` 冻结语法树，`read` 做相同的事（Mora 无 AST，两者等价于把源码文本作为可执行代码载体）

**`call_builtin_macroexpand(args, env)`** — 展开宏
- 参数：`macro_name: String`, `expr_code: Value::Code` (可选，当前宏系统为 by-example，无 compile-time source 展开，故先返回宏体源码文本作为"展开结果")
- 实际上 Mora 宏是 runtime-by-example（非 compile-time source 变换），因此 `macroexpand` 的实现是：查找 env 中名为 `name` 的 `Value::Macro`，返回 `Value::Code(macro_source_repr)` — 但 Mora 不存储宏源码文本。
- **更实用的实现**：`macroexpand(name, ...args)` 直接执行宏（绑定 args → run_mir），返回结果作为展开值。这与 CL 的 `macroexpand` 语义对齐（执行宏函数得到展开形式的求值结果）。
- 签名：`macroexpand("when", ["x > 0", "print(x)"])` → 执行宏 body → 返回结果 Value

## 风险与权衡

- **gensym 计数存储位置**：放在 `CoreRuntime` 而非独立全局。Pregel worker 场景下每个 worker 有独立计数器，跨 worker 可能冲突。但 Mora 宏在同一 worker 内展开，且 `g{n}` 形式的符号名仅在宏展开上下文使用（非跨 worker），因此可接受。
- **macroexpand 语义**：Mora 宏是 by-example（运行时求值），非 compile-time source 变换。`macroexpand` 执行宏 body 并返回结果，语义等价于 CL `macroexpand` 求值展开形式。这是 Mora 无 AST 架构下的正确映射。
- **不修改 `Value` enum**：符号以 `Value::String` 表示，符合 Mora 现有模式（`eval`/`quote` 也不引入新 Value 变体）。
