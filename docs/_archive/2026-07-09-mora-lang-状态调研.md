## 0. TL;DR

mora-lang 是**一门 AI-native 脚本语言**，定位是「AI Agent 编排 DSL + 脚本语言」混合体。当前在 v0.51，4 门禁全绿（build / 606 tests / fmt / clippy `-D warnings`）。**3 大调研结论**：

1. **方向**：5 阶段 Plateau 演进，**当前在 Plateau A**（结构债清偿，v0.52–v0.55）。核心蜕变目标是「**AI 编译时化**」——让 AI 既是一等运行时公民（p"..." / agent）也成为一等编译时公民（生成代码）。最终范式定位是「**第一门 AI 系统语言**」。
2. **集成**：6 个边界清晰的接入点 — ①CLI `mora` ②HTTP server ③MCP server（stdio JSON-RPC）④LSP server（`mora-lsp`，6 个编辑器客户端）⑤Python/HTTP REST（web.fetch + 第三方 sandbox）⑥ vendored scripts（`mora install`）。
3. **薄弱**：①`Interpreter` 是 33 字段 god object / ②`builtins.rs` 5030 行 ③444 处 `unwrap()` ④v0.50/0.51 4 个 P0 占位未通（Send 派发、Reducer::Merge、typeck CommandGoto/SendTargets）⑤Parser 占位（closure 值转换）⑥AST-aware formatter 占位。

## 1. 发展方向

### 1.1 范式定位（高层）

> Mora 是一门面向 **AI-native 自动化**的脚本语言——一段代码同时描述 LLM 调用、HTTP/MCP 服务、长期记忆、多 Agent 协作与可观测。

**核心论点**（`METAMORPHOSIS_ROADMAP.md` §0）：
- 通用蜕变路径（VM / HM / 包管理 / FFI）每个脚本→系统语言都走过，mora 走没有优势
- mora 独有路径是「**AI 编译时化**」——AI 既是运行时一等公民，也是编译时一等公民
- 终点不是「追上 Rust」而是「**定义 AI 系统语言**」——范式开创者，不是追赶者

### 1.2 3 个相变（α / β / γ）

| 相变 | 名称 | 含义 | 启动版本 | 当前状态 |
|------|------|------|----------|----------|
| **α** | IR 化 | AST → MIR → 解释/编译，MIR 解释器替代 AST 解释器 | Plateau C（v0.66+） | 🔧 α.0 / α.2 部分接通（702 行 MIR 模块） |
| **β** | 形式化 | 操作语义 + property test + HM 推断，钉死语义 | Plateau B（v0.56+） | ⏳ 待启动（spec §13 有 T-Num/T-Str/T-Add 骨架） |
| **γ** | AI 编译时化 | AI 在编译时生成代码，经 typeck 静态检查 | Plateau B 末尾启动，Plateau C 成熟 | ⏳ 概念阶段（Haxe expression macro + mora AI 原语融合） |

**关键顺序约束**：β 必须在 γ 之前（AI 生成代码需要形式化 typeck 做安全网）；α 的 MIR 定义提前到 B 末尾（给 γ 提供「AI 宏生成 MIR」目标）。

### 1.3 5 阶段 Plateau 演进（短中期路线）

| Plateau | 主题 | 版本区间 | 当前进度 | 退出 gate |
|---------|------|----------|----------|-----------|
| **A** | **结构债清偿** | v0.52 – v0.55 | 🟡 **进行中** | 6 facade + Command/Send Value 变体 + JSON 统一 + unwrap ≤30 + 700+ tests |
| **B** | **形式化** | v0.56 – v0.65 | ⏳ 未启动 | 核心语义有操作语义 + property test + HM 可选 + 基准套件 |
| **C** | **性能** | v0.66 – v0.75 | ⏳ 未启动 | 字节码 VM（仅当基准证明解释器是瓶颈） + 流式背压 + GPU 子集 |
| **D** | **生态** | v0.76+ | ⏳ 未启动 | 包注册表 + FFI + 第三方工具链 + 可选拆 workspace |

**不变量（护栏，I1-I5）**：
- **I1** AI-native 一等公民（p"..." / orchestrate / agent 永远原语，不变库）
- **I2** 渐进复杂度（3 行脚本能跑，大型系统能建）
- **I3** 零 async runtime 红线（解释器保持 sync；tokio 只在传输层）
- **I4** 永远不到达 v1.0（蜕变是过程不是终点）
- **I5** 可回退性（每个相变有 fallback：`MORA_INTERP=ast` / `MORA_NO_HM=1` / `MORA_NO_AI_MACRO=1`）

### 1.4 近版本（v0.52–v0.55）具体工作项

从 `ARCHITECTURE_DESIGN_v2.md` §6 提取的 Plateau A 执行顺序：

### 2.2 6 个集成点详解

#### ① CLI 入口 — `mora <file>`

- **文件**：`src/main.rs`（1043 行），入口函数 `run_file(path)`
- **使用方**：终端用户、`mora install` 的 vendored scripts、CI 脚本
- **接口**：
  ```bash
  mora <file.mora>                 # 执行脚本
  mora --repl                      # 交互式 REPL
  mora --check <file>              # 仅类型检查
  mora --version / --help
  mora record / replay / diff / stats / timeline / snapshot
  mora mcp tool-list / tool-search / toolsets
  ```
- **通信**：无网络，纯本地 stdio（除 AI HTTP 外）
- **状态**：✅ 稳定（v0.08.5 修复 `mora run <file>` 子命令命名问题）

#### ② HTTP server — `serve as http`

- **文件**：`src/http_server.rs`（tokio async，0.x 演进中）
- **使用方**：外部 HTTP 客户端（curl / fetch / 浏览器）
- **接口**：
  ```mora
  serve as http on port 3000 do
    GET "/health" -> fn(req) return {status: "ok"} end
    POST "/chat" -> fn(req) return deep(p"...") end
  end
  ```
- **通信**：HTTP/1.1，tokio listener
- **状态**：⚠️ sync/async 边界已固化为 ADR-002（async 只在传输层，sync 解释器经 `spawn_blocking` 调）

#### ③ MCP server — `serve as mcp`

- **文件**：`src/mcp_server.rs`（tokio async + stdio JSON-RPC 2.0）
- **使用方**：Claude Desktop、Claude Code、其他 MCP 客户端
- **接口**（MCP 协议）：
  ```
  initialize → capabilities: {tools: {listChanged: false}}
  initialized (notification)
  tools/list → 列出脚本里 tool 块
  tools/call → 调 tool handler
  ```
- **通信**：JSON-RPC 2.0 over **stdin/stdout**（Content-Length framing，**复用 LSP transport**）
- **数据**：`McpTool { name, description, parameters: JSON Schema, handler: Value::Closure, toolset }`
- **状态**：✅ 稳定（v0.04 内嵌到解释器，v0.24 加 ToolsetConfig）

#### ④ LSP server — `mora-lsp`

- **文件**：`src/bin/lsp.rs`（二进制）+ `src/lsp/`（7 文件：server / transport / json / 4 providers）
- **使用方**：6 个编辑器插件（VSCode / Neovim / Helix / Sublime Text / Vim / Emacs）
- **接口**（LSP 协议，stdio JSON-RPC）：
  - `hover` — 悬停文档
  - `completion` — 代码补全
  - `definition` — 跳转定义
  - `references` — 引用查找（含定义点，v0.51 P0-8）
  - `documentSymbol` — 大纲
  - `documentFormatting` / `documentRangeFormatting` — 基础缩进格式化
  - `rename` — 跨引用重命名
  - `semanticTokens` — 语法高亮增强
  - `foldingRange` — if/for/task 块折叠
  - `publishDiagnostics` — typeck 错误推送
- **测试**：`cargo run --example lsp_smoke` 启动 `mora-lsp` 子进程 + 模拟 LSP 客户端
- **状态**：⚠️ 大部分基础能力 ✅；**AST-aware formatter 占位**（P0-8 之一未通）

#### ⑤ Web/HTTP 出站 — `web.fetch` + `json.*` + `file.*`

- **文件**：`src/flow.rs`（JSON 转换）+ 内置 `web.fetch`（基于 ureq 同步 HTTP）
- **使用方**：脚本作者
- **接口**：
  ```mora
  let resp = web.fetch("https://api.openai.com/v1/chat/completions")
  let parsed = json.parse(resp.body)
  file.write_text("/tmp/x.txt", "hello")
  ```
- **通信**：同步 HTTP（ureq 库），**与解释器同步树遍历契合**
- **状态**：✅ 稳定（v0.04 引入）

#### ⑥ Vendored scripts — `mora install <url>`

- **文件**：`src/main.rs::install_package`（CLI 子命令）+ `vendor/` 目录
- **使用方**：包作者 + 包消费者
- **接口**：
  ```bash
  mora install <url>    # 装到 vendor/
  ```
- **状态**：🟡 **早期**（Plateau D 才正式做包注册表；当前 vendor/ 机制已可用）

### 2.4 集成架构关键决策

- **ADR-002 Sync-first 解释器**：解释器（BC1-BC2 + 所有 facade）保持 sync；传输层（BC6）用 tokio；桥 = `tokio::task::spawn_blocking` + channel。结果：守住 C1 红线，sync 解释器与 sync HTTP（ureq）天然契合。
- **BC 边界（ADR-001 9 个 bounded context）**：Language core / Execution / AI / Orchestration / Persistence / Transport / Sandbox / Document / Scheduling — 每个 BC 有独立模块边界（`mod` 可见性 + `pub(crate)`）。

### 3.2 结构性债（Plateau A 主题）

#### 🔴 1. `Interpreter` 是 33 字段 god object

- **位置**：`src/interpreter/mod.rs:203-275`
- **影响**：每新增功能必改 struct + 3 个构造函数 + 43 行 Clone
- **后果**：`builtins.rs` 因此膨胀到 5030 行；6 个 BC 的逻辑相互污染
- **根源**：6 个 BC 的状态直接塞进同一个 struct — 实际上是手写 service locator
- **解法**：ADR-001 抽 6 个 Domain Facade（AiRuntime / OrchRuntime / PersistRuntime / SandboxRuntime / RegistryRuntime / InfraRuntime）
- **状态**：🟡 进行中，**当前在 Plateau A 退出 gate 上**

#### 🔴 2. `builtins.rs` 5030 行

- **位置**：`src/interpreter/builtins.rs`
- **影响**：单文件 5000+ 行，diff 冲突高、code review 困难、独立测试不可能
- **解法**：拆为 `builtins/{file,sandbox,ai,...}.rs`（ADR-001 + ADR 拆分大文件）
- **状态**：⏳ Plateau A 工作项（待 facade 抽完自然落地）

#### 🔴 3. 444 处 `unwrap()` 还在涨

- **分布**：
  - `interpreter/builtins.rs`：85 处（最密）
  - `interpreter/orchestrate_v2.rs`：19 处
  - `interpreter/mod.rs`：9 处
  - `interpreter/dispatch.rs`：2 处
  - 其他散布于 sandbox / checkpoint / event / plan / refine 等
- **风险**：用户输入触发 panic → 整个解释器崩溃
- **历史**：v0.52 时 334，v0.51 时 378，**现在 444**（+66，涨幅加速 — 与 v0.50/0.51 新模块相关）
- **解法**：每个 facade PR 附带验收「不增 unwrap」+ 长期降到 ≤30
- **状态**：🟡 持续推进，未达 Plateau A 退出 gate（≤30）

#### 🟡 4. JSON Value 重复（3 套）+ 序列化器重复（4 套）

- **位置**：`flow::json_to_value` / `lsp::json::Value` / transport 层 + 4 套手写序列化器
- **影响**：认知负担 + 维护成本
- **解法**：ADR-004 统一到单一 `json::Value`（以 `lsp::json::Value` 为基础），4 套序列化器收敛为 `to_string` / `from_str`
- **约束**：**不引 serde**（C2 哲学）
- **状态**：⏳ Plateau A 工作项（待启动）
