## 1. 背景与目标

### 问题描述

项目中有多个大文件，单文件行数超过 2000 行，可维护性差：

| 文件 | 行数 | 问题 |
|------|------|------|
| `src/interpreter/mod.rs` | 3402 | 包含语句执行、表达式求值、模式匹配等多种职责 |
| `src/typeck.rs` | 2838 | 类型定义、类型检查、测试混在一起 |
| `src/parser_v2.rs` | 2609 | 语句解析、表达式解析、辅助函数混在一起 |
| `src/record.rs` | 2091 | 序列化、差异比较、审计、快照等功能混在一起 |
| `src/lsp/providers.rs` | 1092 | 9 个 LSP 功能混在一个文件 |

### 目标

- 每个文件职责单一，便于理解和维护
- 函数按功能分组，提高代码可读性
- 模块间依赖关系更清晰
- 保持所有测试通过，行为不变

## 3. 拆分策略设计

### 原则

1. **单一职责**：每个模块只负责一件事
2. **最小接口**：模块间通过 `pub(super)` 或 `pub` 暴露必要接口
3. **保持兼容**：拆分后所有测试必须通过
4. **逐步验证**：每拆分一个模块就运行测试

### Rust 模块化机制

Rust 支持在同一结构体上定义多个 `impl` 块，可以分布在不同文件中：

```rust
// src/parser_v2/mod.rs
pub struct ParserV2 {
    tokens: Vec<Token>,
    current: usize,
    arena: AstArena,
}

// src/parser_v2/statements.rs
use super::*;
impl ParserV2 {
    pub(super) fn let_declaration_exported(...) { ... }
}

// src/parser_v2/expressions.rs
use super::*;
impl ParserV2 {
    pub(super) fn expression(...) { ... }
}
```

### 4.2 创建 execute.rs

提取语句执行逻辑到独立文件：

```rust
// src/interpreter/execute.rs
use super::*;
use crate::ast_v2::{AstArena, NodeId, StmtKind};
use crate::value::{Environment, FlowSignal, Value};

impl Interpreter {
    /// 执行语句（主入口）
    pub fn execute(
        &mut self,
        stmt_kind: &StmtKind,
        arena: &AstArena,
    ) -> Result<FlowSignal, String> {
        match stmt_kind {
            StmtKind::Let { name, init, exported, .. } => {
                self.execute_let(name, *init, *exported, arena)
            }
            // ... 其他语句类型
        }
    }

    /// 执行 let 绑定
    fn execute_let(
        &mut self,
        name: &str,
        init: NodeId,
        exported: bool,
        arena: &AstArena,
    ) -> Result<FlowSignal, String> {
        let value = self.evaluate(init, arena)?;
        self.environment
            .lock()
            .expect("environment mutex poisoned")
            .define(name.to_string(), value, exported);
        Ok(FlowSignal::None)
    }
    // ... 其他执行函数
}
```

### 6.4 处理可见性问题

跨模块调用需要将函数标记为 `pub(super)`：

```rust

pub(super) fn expression(&mut self) -> NodeId { ... }
```

## 9. CI/CD 问题修复

### 9.1 rustfmt 格式检查失败

**问题**：拆分后的文件格式不符合 rustfmt 规范。

**解决**：
```bash
cargo fmt -- src/interpreter/mod.rs src/interpreter/execute.rs ...
```

### 9.2 Windows 路径问题

**问题**：测试使用硬编码的 `/tmp/` 路径，在 Windows 上失败。

**错误信息**：
```
memory save/load should work: "memory.save: The system cannot find the path specified. (os error 3)"
```

**解决**：使用 `std::env::temp_dir()` 获取跨平台临时目录：

```rust
#[test]
fn test_memory_save_load() {
    use std::env;
    let tmp_dir = env::temp_dir();
    let tmp_file = tmp_dir.join("mora_test_memory.json");
    let tmp_path = tmp_file.to_string_lossy().replace('\\', "/");
    let src = format!(r#"
task main()
  memory.store("key1", "value1")
  memory.save("{}")
end
"#, tmp_path);
    run(&src).expect("memory save/load should work");
    let _ = std::fs::remove_file(tmp_file);
}
```

### 9.3 Docker 构建失败

**问题**：Dockerfile 使用的 Rust 版本太旧（1.86），不支持 edition 2024。

**解决**：更新 Dockerfile 使用最新 Rust 版本：

```dockerfile
# 旧版本
FROM rust:1.86-alpine AS builder

# 新版本
FROM rust:alpine AS builder
```

### 9.4 Release body 包含内部文档引用

**问题**：Release body 引用了 `docs/` 文件夹中的内部文档。

**解决**：更新 `.github/workflows/release.yml`，移除内部文档引用。

### 9.5 Docker 镜像未包含在 Release 中

**问题**：`release` job 只依赖 `build`，不依赖 `docker`。

**解决**：修改依赖关系：

```yaml
release:
    name: Publish GitHub Release
    needs: [build, docker]  # 添加 docker 依赖
```

## 11. 经验总结

### 11.1 拆分原则

1. **先分析再动手**：理解代码结构和调用关系
2. **逐步验证**：每拆分一个模块就运行测试
3. **保持行为不变**：拆分只是重构，不改变功能
4. **遵循项目约定**：使用项目现有的命名和组织方式

### 11.2 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 私有函数无法跨模块调用 | 可见性限制 | 使用 `pub(super)` |
| 导入路径错误 | 模块层级变化 | 使用 `use super::*` 或 `use crate::...` |
| 格式检查失败 | 拆分时格式不一致 | 运行 `cargo fmt` |
| 测试失败 | 路径或环境差异 | 使用跨平台 API |

### 11.3 工具推荐

- `wc -l`：统计文件行数
- `grep -n`：查找函数定义
- `sed -n 'start,endp'`：提取文件片段
- `cargo check`：快速检查编译
- `cargo clippy`：代码质量检查
- `cargo fmt`：格式化代码
- `gh`：GitHub CLI，管理 Release
